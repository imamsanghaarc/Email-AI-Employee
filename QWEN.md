# AI Employee - QWEN Context

## Project Overview

**AI Employee** is a modular, production-ready local AI employee framework built on a structured Obsidian vault system. It provides multi-tier autonomous operations ranging from basic file monitoring (Bronze Tier) to advanced scheduling with human-in-the-loop approvals (Silver Tier) and full autonomous business operations (Gold Tier).

### Core Purpose
The system acts as an intelligent automation layer that:
- Monitors an Obsidian vault inbox for new tasks/files
- Generates structured task files and execution plans
- Processes tasks autonomously with LLM-driven reasoning
- Integrates with external business systems (Odoo, social media, email)
- Maintains comprehensive audit trails and dashboards
- Supports human approval workflows for sensitive operations

### Architecture

The project follows a **vault-centric architecture** with these key components:

#### 1. Vault Structure (`AI_Employee_Vault/`)
- **Inbox/**: Entry point for all new files and raw data
- **Needs_Action/**: Automated task files generated by the watcher
- **Needs_Approval/**: Tasks requiring human authorization (Silver Tier)
- **Done/**: Archive for completed tasks
- **Plans/**: Strategic execution plans for multi-step tasks
- **Reports/**: Generated reports (e.g., CEO Weekly Briefing)
- **Errors/**: Failed tasks moved here for manual review

#### 2. Tier System

**Bronze Tier** (Basic Monitoring):
- `watcher.py`: Monitors Inbox every 5 seconds, creates task files
- `run_ai_employee.py`: Processes tasks, updates dashboard
- `log_manager.py`: Rotates logs exceeding 1.5MB

**Silver Tier** (Advanced Operations):
- `scripts/run_ai_employee.py`: Central scheduler with daemon mode
- `scripts/watch_inbox.py`: Enhanced watcher with AI triggering
- `scripts/task_planner.py`: LLM-driven task planning (OpenRouter/Gemini)
- `scripts/ralph_wiggum_loop.py`: Autonomous execution loop with safety checks
- `scripts/request_approval.py`: Human-in-the-loop approval system

**Gold Tier** (Full Autonomy):
- `scripts/generate_ceo_briefing_pro.py`: Weekly business intelligence reports
- Social media posting (LinkedIn, Facebook, Twitter, Instagram)
- Odoo ERP integration via MCP server
- Business MCP for external actions

#### 3. MCP Server Integrations (`mcp/`)
- **odoo-mcp**: JSON-RPC integration with Odoo Online for accounting
- **ex-business-mcp**: General business actions (email, LinkedIn)

#### 4. Agent Skills (`.agents/skills/`)
18 specialized skills encapsulating specific capabilities:
- **accounting-manager**: Business finance tracking
- **ceo-briefing**: Weekly executive report generation
- **cron-scheduler**: Time-based task automation
- **error-recovery**: Automated error handling and retry
- **facebook-poster**: Facebook automation via Playwright
- **file-watcher**: Vault monitoring and task generation
- **gmail-send**: SMTP email sending
- **gmail-watcher**: Gmail monitoring for task creation
- **human-approval**: Blocking verification workflow
- **linkedin-business-poster**: LinkedIn business content posting
- **linkedin-post**: Direct LinkedIn posting via Playwright
- **linkedin-watcher**: LinkedIn activity monitoring
- **mcp-server**: External action protocol server
- **scheduler-silver-tier**: Continuous orchestration loop
- **social-summary**: Social media activity logging
- **task-planner**: LLM-driven execution planning
- **twitter-poster**: Twitter/X automation
- **vault-file-manager**: Task state transitions

## Technologies & Dependencies

## Building and Running

### Prerequisites
```bash
# Install Python dependencies (check requirements.txt if exists)
pip install playwright requests
playwright install

# Copy and configure environment
cp .env.example .env
# Edit .env with your credentials
```

### Bronze Tier (Basic Operations)
```bash
# Start vault watcher (monitors Inbox every 5s)
python watcher.py

# Process pending tasks (single run)
python run_ai_employee.py --once

# Rotate logs
python log_manager.py
```

### Silver Tier (Advanced Operations)
```bash
# Start daemon mode (continuous execution every 5 minutes)
python scripts/run_ai_employee.py --daemon --interval 300

# Single execution pass
python scripts/run_ai_employee.py --once

# Check system status
python scripts/run_ai_employee.py --status
```

### Gold Tier (Full Autonomy)
```bash
# Generate weekly CEO briefing
python scripts/generate_ceo_briefing_pro.py

# Run autonomous execution loop
python scripts/ralph_wiggum_loop.py

# Post to social media
python scripts/linkedin_post_direct.py "Your content here"
python scripts/facebook_post.py "Your content here"
python scripts/twitter_post.py "Your content here"
```

### Error Recovery
```bash
# Handle a failed task
python scripts/error_recovery.py <file_path> <error_message> --retry_cmd "<command>"
```

## Key Workflows

### 1. Task Processing Pipeline
```
File added to Inbox/ 
  → watcher.py detects file (5s interval)
  → Creates task file in Needs_Action/
  → task_planner.py generates execution plan (LLM or template)
  → ralph_wiggum_loop.py executes plan steps
  → Risky actions trigger human approval request
  → Completed tasks moved to Done/
  → Dashboard.md and logs updated
```

### 2. Human Approval Workflow
```
Risky action detected (post, send, delete, etc.)
  → scripts/request_approval.py creates file in Needs_Approval/
  → Execution blocks until human responds
  → Human writes APPROVED or REJECTED in file
  → Script renames file with .approved/.rejected suffix
  → Execution continues or aborts based on response
```

### 3. CEO Briefing Generation
```
scripts/generate_ceo_briefing_pro.py
  → Pulls financial data from Odoo (JSON-RPC)
  → Reads social media logs
  → Analyzes completed tasks
  → Checks system health metrics
  → Generates comprehensive weekly report in Reports/
```

### 4. Error Recovery
```
Task fails during execution
  → Logged to logs/errors.log
  → File moved to AI_Employee_Vault/Errors/
  → Background retry scheduled (5-minute delay)
  → Retry executes
  → Success: file restored to Needs_Action/
  → Failure: file remains in Errors/ for manual review
```

## Development Conventions

### File Naming
- Task files: `task_<name>.md` or `<descriptive_name>.md`
- Plans: `Plan_YYYY-MM-DD_HH-MM-SS.md`
- Error files: `error_YYYYMMDD_HHMMSS_<original_name>.md`
- Approval files: `approval_<timestamp>.md`

### Markdown Task Format
Tasks use YAML frontmatter and structured bodies:
```markdown
---
type: file_review
status: pending
priority: medium
created_at: 2026-04-11 14:54:44
related_file: ["filename.md"]
---

# Task File: Review filename.md

## Description
...

## Checklist
- [ ] Action item 1
- [ ] Action item 2
```

### Logging
- **System_Log.md**: High-level AI activities
- **logs/actions.log**: Detailed execution history
- **logs/ai_employee.log**: Silver Tier scheduler log
- **logs/ralph_wiggum.log**: Autonomous loop activities
- **logs/errors.log**: Error tracking and recovery
- **Social_Logs.md**: Social media posting history

### Safety Mechanisms
1. **No Simulation Rule**: Always perform actual file operations
2. **Atomicity**: Each task fully completes before next begins
3. **Max Iterations**: Autonomous loops have iteration limits
4. **Risk Detection**: Keywords (post, send, delete, etc.) trigger human approval
5. **Lock Files**: Prevent duplicate daemon instances
6. **Graceful Shutdown**: Handle Ctrl+C and release resources
